# 视频基调风格（全流水线统一，后续出片一律按此风格）

## 定位：《辣妹快报》——新闻联播式美食播报

用新闻主持人的风格做美食推荐：**辣条妹就是出镜主播**，整期视频像一档美食新闻栏目，
右上角常驻一扇「本期美食」窗口，从各个角度介绍本期推荐的美食。

## v15 全程主播口播（`VIDEO_STYLE=host`，2026-10-06 定稿，当前默认）

辣条妹的要求是「全程就她一个人拿锅铲激情介绍右上角那盘菜」，所以默认基调从“穿插图卡”改成**镜镜在镜**：

- 分镜：5-7 镜，**每镜 `hh=true` + `talk=true`**，`vo ≤18 字`（≈4 秒）——台词一长，模型就会在镜头里
  自己推特写、换背景，开头一秒还是闭嘴笑，观感直接就是“口型跟台词对不上”；
- 首帧统一用 **`data/uploads/charref/latiaomei-host-916.jpg`**（“说话态”半身定妆图：举锅铲、张嘴、
  身后一桌菜），不再用灰底全身立绘——那张会让模型每次都从“站姿证件照”走景走到“餐厅特写”；
- 出片时把逐镜片段拼成**一条连续主播轨道**（`render.js: concatVideos`），成片里只有一个 `<video>`：
  1.6G 内存的机器同时解码 7 段视频会把 Chrome 打死（实盘 `render_cancelled_parent_exited`）；
- 每镜片段过三道体检（`happyhorse.js: inspectClip`）：**全黑/全白**（废片，实盘出现过 4s 黑屏）、
  **几乎静止**（卡帧废片）、**首尾漂移 >45**（镜头内走景）；判废自动重试一次，仍废退回静帧图卡（绝不黑屏）；
- **口型能力边界（实测）**：`happyhorse-1.1-i2v` 会把 `audio_url` 当成“这条片子的配音”塞进成片音轨，
  但嘴部运动与语音包络的相关度实测只有 -0.15~0.12，即**没有音素级口型驱动**；本网关上
  `videoretalk / emo-v1 / wan2.2-s2v` 全部返回 `Model not exist`。所以现在的做法是：
  ① 成片配音 = 片段自带音轨（声音和嘴出自同一次生成，至少不错位）；② 景别固定半身，嘴占比小；
  ③ 下三分之一字幕条同步显示台词。要真·口型同步，得接能驱动口型的模型（见 README「口型」条）。

## 分镜叙事结构（时长跟着内容走，2026-10-06 修订）

> **时长铁律**：成片不做固定时长（旧版每期硬凑 50s 已废除）。每镜长度 = 该镜旁白实测
> 朗读时长 + `VO_TAIL`，happyhorse 镜头长度 = 片段实测时长，总长 = 各镜之和；
> 分镜数量按内容体量定（一般 5-9 镜），内容少就短，**禁止为凑时长注水写台词**。

1. **开场（第 1 镜，硬规定）**：辣条妹真人出镜开口播报，由 happyhorse 用该镜旁白配音
   （audio_url）驱动口型，嘴型跟台词一致；开场词固定句式「各位吃货观众晚上好，我是辣条妹，
   欢迎收看辣妹快报！今日给大家推荐一道菜——XX，嘎嘎香，够我干六碗米饭！」；镜头长度跟随音频自动对齐；
2. **隔镜有人**：每隔 1-2 镜必须有一个出镜镜头（全片有人镜头占比过半，禁连 3 镜没人），动作多样：
   插播点评（说话镜 talk=true，音频驱动口型）、端菜上桌、揭盖尝香、夹筷试吃、竖锅铲介绍、
   解围裙走向灶台、绕桌走动等（动作镜 talk=false，闭嘴）；
3. **像讲故事**：来历/做法看点 → 口感层次（先辣后香、锅气、落胃）→ 分量价格/环境人气 → 点单攻略；
4. **收尾 CTA**：主播出镜收束，重申金句「够我干六碗米饭」。

## 声音（2026-10-05 定稿）

- **不要背景音乐**：人声清楚、画面优先（audio.js BGM 默认关，需要时 .env `BGM_ENABLED=1` 显式打开）；
- **口型铁律（2026-10-06）**：说话镜（talk=true）的成片配音**用 happyhorse 片段自带的那条音轨**
  （`audio.js: useClipAudio`），不再铺 edge-tts 的原 mp3——实测模型拿原 mp3 驱动口型后，
  回片里的音轨起口比原文件晚 ~0.85s、中段还有 ±0.3s 漂移，铺原 mp3 必然“唇形对不上台词”
  （自测量到错位 1120ms，改用片段自带音轨后 lag=0ms、同源度 0.99）；
- happyhorse 片段下载后统一重编码成 30fps + 每秒一个关键帧（`happyhorse.js: normalizeClip`）：
  模型回片关键帧很稀（实测间隔 3s+），hyperframes 会告警 sparse keyframes 并出现抽帧卡帧，
  也是嘴型错位的一个来源；
- 说话有激情：edge-tts 分两档情绪——普通镜 rate+15%/pitch+4Hz；金句镜（开场/收尾/含
  “嘎嘎香”“六碗米饭”“！”）rate+28%/pitch+12Hz/音量+8%；
- 台词必带人设记忆点：口头禅「嘎嘎香」、招牌金句「这盘菜，够我干六碗米饭！」、杭州话「落胃」（全片至少各一次）。

## 文案口吻

- 旁白 vo：新闻主播腔架子 + 辣条妹的激情与烟火气，短句利落、先事实后点评，多用感叹句，
  像拉街坊下馆子不是冷面念稿；说话镜（talk=true）的 vo 就是她嘴里念的词，会喂给视频模型驱动口型；
- 全片至少一次「嘎嘎香」、一次「这盘菜，够我干六碗米饭」式金句；
- 不写营销号腔、不堆形容词、不用绝对化用语（广告法）；
- 旁白（vo）与画面字幕（title/sub）必须说同一件事。

## 分镜 JSON 字段约定（新闻风格新增）

- `pip`：右上角美食窗口素材序号（1-N，可与 img 相同；无素材填 0）。出片时先于 hh 片段解析成 `food` 落盘文件名，保证主播镜头里窗口始终有美食画面。
- `hh=true` 的镜头：`hh_prompt` 写动作与镜头运动；首帧缺省用 9:16 主播立绘（`latiaomei-front-916.jpg`，
  出竖屏片段不裁切），指了实拍素材才用 asset；说话镜（`talk=true`）出片时会把该镜旁白 mp3
  发到 `/uploads/vo-tmp/` 公网可达 URL，作为 `input.audio_url` 喂给 happyhorse 驱动口型，
  请求秒数 = `ceil(配音长度)+1`（留起口余量，免得句尾被截）；镜头槽位取**片段实测时长**，
  本镜配音取**片段自带音轨**，两者同源，唇形与台词必对齐（片段没音轨才退回 edge-tts 版）。
